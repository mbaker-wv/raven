How the Security Check works

What each check looks at, and how the vulnerability scan actually works.
Basic checks
→

Server bind address — reads the actual launch args to confirm Raven only listens on 127.0.0.1 (this machine), not reachable from your network.

→

Secret key file permissions — your Claude/B2 secrets are encrypted at rest using .raven.key; this confirms that file isn't readable by other accounts on this machine, which would defeat the point of encrypting it.

→

Debug/reload mode — flags whether the server is running with --reload. Harmless on localhost, just a heads-up if this were ever exposed beyond it.

→

Database file — reports where your data lives and its size, mostly informational.

Vulnerability scanning
!

Dependency vulnerabilities (pip-audit) is the actual vulnerability scan — it cross-references your installed Python packages (pinned in requirements.txt) against public CVE/advisory databases and flags any with a known, published vulnerability.

→

Outdated packages is different from a vulnerability — it compares your installed version of each package against the latest release on PyPI, so you know if you're behind even before a CVE exists for the old version.

→

Ollama version does the same comparison for Ollama itself, checked against its latest release on GitHub, since it's a real dependency this app talks to.

Runs automatically
→

All of the above runs on its own about 15 seconds after Raven starts, then every 24 hours — you don't have to remember to click the button.

→

Every run is saved. Past runs below shows history, and a regressed note appears above the results if something that used to pass is now failing, or a failure's details changed since the last check.
